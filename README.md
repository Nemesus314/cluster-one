# Cluster One

*Fünf WordPress-Plugins auf einem gemeinsamen Boden, dazu zwei Werkzeuge. / Five WordPress plugins on one common ground, plus two tools.*

WordPress 7.0+ (getestet mit 7.1 / tested up to 7.1) · PHP 7.4+ · GPL-2.0-or-later

**Der Boden.** Die fünf Häuser teilen sich einen Satz Dateien in `includes/` (kern, kasper, kranz, menue, speicher, anti-babel, feynman), in jedem Haus eine eigene Kopie, byte-gleich bis auf die Text-Domain. Ein Riegel `function_exists` lässt die Kopien nebeneinander leben; das Kasper-Register zeigt auf dem Knoten, wer da ist und welchen Boden-Stand er trägt. Die beiden Turings tragen den Boden mit Absicht nicht.

**Installation, einzeln:** einen Ordner nach `wp-content/plugins/` legen und aktivieren. Jedes Haus läuft für sich.

**Installation als Satz, mit Turing:** den Ordner `cluster-one-hangar/` aus diesem Repository nach `wp-content/` kopieren (er trägt `.htaccess` und `index.php`, damit niemand hineinschaut), die Zips der Häuser hineinlegen, Turing aktivieren und den Satz aufspielen lassen. Turing prüft jedes Paket, bevor es den Knoten anfasst. Die Zips liegen unter *Releases* dieses Repositories, byte-gleich mit dem, was auf den Knoten läuft. Ein von GitHub erzeugtes Repository-Zip taugt dafür nicht: sein Ordnername heißt anders, Turing lehnt es ab.

**Stand:** Für das offizielle WordPress-Plugin-Verzeichnis bestimmt; eingereicht wird ein Plugin nach dem anderen, bis dahin ist GitHub die Quelle. Turing selbst bleibt auf GitHub.

**Mehr:** in jedem Ordner `readme.txt` (WordPress-Format), `why.txt` (warum es das gibt) und ein eigenes README. Nicht mit Cluster One verwechseln: das Child-Theme Prometheus und das Skript Lamarr liegen in eigenen Repositories.

## English

**The ground.** The five houses share one set of files in `includes/` (kern, kasper, kranz, menue, speicher, anti-babel, feynman), each house carrying its own copy, byte-identical except for the text domain. A `function_exists` latch lets the copies coexist; the Kasper register on the node shows who is there and which ground version each carries. The two Turings carry no ground on purpose.

**Install one by one:** put a folder into `wp-content/plugins/` and activate it. Every house runs on its own.

**Install as a set, with Turing:** copy the folder `cluster-one-hangar/` from this repository into `wp-content/` (it carries `.htaccess` and `index.php` so nobody can look inside), put the houses' zips in, activate Turing and let it install the set. Turing checks every package before it touches the node. The zips are attached under *Releases* of this repository, byte-identical to what runs on the nodes. A repository zip generated by GitHub does not work here: its folder name differs, Turing rejects it.

**Status:** Meant for the official WordPress plugin directory; submission will go one plugin at a time, until then GitHub is the source. Turing itself stays on GitHub.

**More:** in every folder `readme.txt` (WordPress format), `why.txt` (why it exists) and a README of its own. Not to be confused with Cluster One: the child theme Prometheus and the script Lamarr live in repositories of their own.
